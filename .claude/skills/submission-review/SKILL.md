# 제출 검토

평가자는 **GitHub에 올라간 것만** 본다: README, 커밋 기록, 결과물(코드, 배포 페이지, 영상). 로컬에만 있는 파일, 아직 push하지 않은 커밋, 대화 내용은 없는 것으로 친다. 검토자는 만든 사람의 설명을 믿지 말고 저장소에서 근거를 직접 찾는다.

## 확인 방법

- 저장소: https://github.com/lgosoup/fruit-measure (기본 브랜치 `main`)
- 파일: `https://raw.githubusercontent.com/lgosoup/fruit-measure/main/<경로>`
- 커밋 기록: `gh api repos/lgosoup/fruit-measure/commits?per_page=100` 또는 GitHub 커밋 화면
- 배포 페이지: https://lgosoup.github.io/fruit-measure/
- 로컬 작업 폴더가 있어도 읽지 않는다. push된 상태만 판단한다.

## 점검 항목

### 1. 저장소
- [ ] Public이고 로그인 없이 열린다.
- [ ] 비밀 값(API 키, 비밀번호)이 커밋되어 있지 않다.
- [ ] 작업용 메모, 강의 자료, 개인 문서처럼 결과물이 아닌 파일이 올라가 있지 않다.

### 2. README (평가의 중심)
- [ ] **프로젝트 소개**: 무엇을, 왜 만들었는지, 사용 방법. 이전 버전보다 무엇이 발전했는지가 드러난다.
- [ ] **PRD와 Todo**: `PRD.md`, `todo.md`로 연결되고 구성이 요약되어 있다.
- [ ] **Todo 변경 내역**: 처음 Todo에 없던 내용(추가·변경·취소)이 무엇인지 README에서 알 수 있고, todo 안에서도 원래 없던 항목임이 눈에 띄게 표시되어 있다. 변경이 하나도 없으면 부족으로 본다.
- [ ] **스킬**: `SKILL.md`가 1개 이상 있고 README에서 찾아갈 수 있다. 각 스킬이 무엇을 하고 실제로 어떻게 쓰였는지 설명이 있다.
- [ ] **느낀 점, 결론**: 실제로 겪은 사례에 근거한다.
- [ ] 문서가 그 자체로 읽힌다: 저장소에 없는 문서나 비공개 자료를 가리키지 않는다.

### 3. PRD·Todo 형식
- [ ] PRD에 목적, 사용자, 핵심 기능, 만들지 않는 것(비어 있지 않음), 기술 조건, 완성 기준이 있다.
- [ ] Todo 할 일마다 번호(`단계-순번`), PRD 근거, 우선순위가 있고, 단계마다 목표와 확인 방법이 있다.
- [ ] 기능 할 일마다 짝이 되는 테스트 할 일이 있다.
- [ ] 마지막 단계가 완성 기준 점검이다.
- [ ] 변경 표시가 `changes.md`의 항목으로 연결되고, 링크가 깨지지 않는다.

### 4. 커밋 기록
- [ ] 한 번에 몰아서 올리지 않고 Todo를 따라 일정한 간격(여러 날)으로 커밋·push했다.
- [ ] 커밋 메시지마다 무엇을 했는지 분명하다(「수정」, 「업데이트」 같은 메시지가 없다). Todo 번호가 있어 todo.md와 맞춰 볼 수 있다.
- [ ] todo에서 체크한 단계마다 대응하는 커밋이 있다.
- [ ] 마감 시각이 주어졌으면, 그 뒤의 커밋은 평가에서 빠진다고 보고 판단한다.

### 5. 실행
- [ ] 배포 페이지가 열린다(응답 200, 스크립트 오류 없음).
- [ ] 이전보다 기능이 줄지 않았다(README·PRD의 기능이 그대로 있다).
- [ ] 이 앱은 안드로이드 폰의 AR이 필요해 PC 브라우저에서는 측정할 수 없다. 그래서 **작동 영상이 저장소에 있고 README에서 찾을 수 있어야 한다.** README에 폰이 필요한 이유가 적혀 있어야 한다.

## 보고 형식

```
## 제출 검토 결과 (검토 시각, 기준 커밋)

| 항목 | 판정 | 근거 | 고칠 점 |
|---|---|---|---|
| README 소개 | 충족 / 부족 / 없음 / 확인 불가 | 파일·줄·커밋 번호 | 구체적으로 |

### 꼭 고쳐야 할 것 (평가에 직접 영향)
### 고치면 좋은 것
### 아직 진행 중이라 판단을 미룬 것
```

- 판정마다 근거(파일 경로, 커밋 번호, URL)를 붙인다. 근거를 찾지 못하면 「확인 불가」로 쓴다. 충족으로 추측하지 않는다.
- 진행 중인 저장소를 검토할 때는 「아직 안 한 것」과 「잘못한 것」을 나눠 쓴다. 마감 전 최종 점검에서는 둘 다 부족으로 본다.
